# 山岚 AI 旅拍

景区 AI 旅拍平台：游客在景区选择模板，用自己的照片制作打卡合拍、AI 换装照片和 AI 换装视频；景区商户购买服务次数、查看收入并申请提现；管理员管理模板、账号、景区与商户绑定，并审核提现。

三种身份统一在「我的」页面登录。

## 快速开始

需要 Node.js ≥ 22.13（使用内置 `node:sqlite`，无需安装数据库）。

```bash
npm run setup      # 安装后端 + 前端依赖
npm run build      # 构建前端到 web/dist
npm start          # http://localhost:3000
```

首次启动会自动初始化数据：三个测试账号、三个景区（老君山已绑定商户）、11 个模板，以及程序生成的插画素材。

开发模式：`npm run dev`（后端 :3000，改代码自动重启）+ `npm run dev:web`（Vite :5173，代理 `/api` 和 `/files`）。

重置数据：`npm run seed:reset`。运行测试：`npm test`（使用独立临时数据目录，走完整三方流程）。

## 原站素材

`server/seed-assets/origin/` 存放模板素材（封面、白模、样片）和 `manifest.json`，`web/public/origin/` 存放界面图标、头像、欢迎页视频等。首次初始化时，老君山会直接使用这些原站模板；如果要改用程序生成的插画，设置 `SEED_SOURCE=generated`。

重新同步原站的公开素材：`node scripts/fetch-origin-assets.mjs`，然后执行 `npm run seed:reset`。金殿合拍的高清合成背景需要管理员权限才能下载，目前仍用生成的背景代替，可以在「管理中心 → 模板管理」中替换。

## 功能

**游客**：选择景区 → 选择服务与模板（点赞、收藏、搜索、热门排序）→ 上传人物照片（身体照必传、人脸照可选）→ 确认价格 → 模拟支付 → 查看制作进度 → 在「我的作品」下载。另有消费订单（含退款记录）、我的人物、我的收藏，以及客服工单（关联订单的工单由该订单所属商户处理，其余由平台处理）。

**商户**：只经营自己绑定的那一个景区。可以购买各服务的使用次数（模拟支付）、查看次数变动明细；查看模板使用统计（成功、失败、收入、点赞收藏、每日趋势）和游客消费流水；在「收入与提现」申请模拟提现（申请后金额冻结，可撤销）；设置服务电话和营业时间；处理本景区的工单。

**管理员**：
- 平台总览，可按景区筛选：消费、标准成本、额度销售、退款、待办事项
- 景区管理：新建、暂停/恢复、单项服务启停、调整游客价和商户额度价、手动调整次数（写入审计日志）
- 商户绑定与解绑：一景区一商户、一商户一景区；解绑前须结清收入且没有制作中的订单，解绑后景区自动暂停
- 全局模板管理：新建、编辑、上架、下架、归档；打卡模板可在背景图上点击设置人物脚底锚点并预览人物高度
- 账号与角色：创建账号、改角色、停用、重置密码
- 流水：消费流水和额度销售
- 提现审核：审核通过 → 模拟打款，或填写原因后驳回（冻结金额释放）
- 标准成本、模拟失败率和登录验证码开关，客服工作台，审计日志

**打印履约**：商户在服务设置中开放打印并填写取件地点后，游客可以对已完成的照片申请打印（6/7 寸，1–10 份），拿到 6 位取件码。商户下载原图打印后标记「可取件」，游客到店出示取件码，商户核对后核销。取件码只有游客能看到。

**兑换码与积分**：管理员给商户分配发放额度；商户或管理员可批量生成兑换码（明文只显示一次），撤销未使用的码会退回占用的额度。游客在「消费记录」中兑换积分并查看明细。积分与在线付款无关。

## 业务规则

| 服务 | 游客价 | 商户额度价 | 默认标准成本 |
| --- | --- | --- | --- |
| 打卡合拍 | ¥0.90 | ¥0.00 | ¥0.00 |
| AI 换装照片 | ¥1.90 | ¥0.30 | ¥0.12 |
| AI 换装视频 | ¥9.90 | ¥2.00 | ¥1.20 |

- 下单时不扣次数；游客模拟支付成功时，扣减该景区对应服务 1 次，订单进入制作队列
- 次数为 0、服务停用、景区暂停或景区未绑定商户时，停止接单
- 制作失败会自动模拟退款，并回补 1 次
- 订单收入归属于下单当时景区绑定的商户，之后换绑商户也不会改变
- 商户可提现 = 成功订单收入 − 冻结中的提现 − 已打款的提现。购买次数是独立支出，不从收入中扣除
- 所有付款、充值、提现都是模拟的，不会发生真实资金流动

## AI 生成

默认 `AI_PROVIDER=mock`：在本地用 sharp 合成图片、用 ffmpeg（通过 `ffmpeg-static` 安装）生成 7 秒竖版视频，**不调用任何外部服务，也不消耗任何余额**。模拟生成可以走通全流程，但画面只是把人物照片贴到场景里，并不是真正的 AI 换装。

- 在管理中心 →「成本设置」把模拟失败率设为 100，即可测试失败退款；人物名称里包含「失败测试」的订单也会失败
- 要接入真实模型，把 `config/runninghub.example.json` 复制为 `config/runninghub.json`，填入各服务的工作流 ID 和节点映射，然后设置 `AI_PROVIDER=runninghub` 和 `RUNNINGHUB_API_KEY`
- 未配置工作流的服务会自动回退到模拟生成
- 打卡合拍的工作流只需输出人物抠像，合成在本地按模板锚点完成
- 已提交给 RunningHub 的任务，在服务重启后会继续轮询原任务，不会重复提交

## 目录结构

```
server/
  index.js          启动入口（首次启动自动初始化数据，并启动制作队列）
  app.js            Express 应用、文件访问签名校验、错误处理
  db.js             SQLite 表结构与查询工具
  domain.js         服务可用性、钱包、额度变动、失败退款
  routes/           auth / public / visitor / tickets / merchant / admin
  ai/               worker（队列）、mock、runninghub、compose（图像合成）、video（ffmpeg）
  seed.js, seed-art.js  初始化数据与程序生成的插画
  test/flow.test.js 端到端流程测试
web/src/
  pages/            游客页面、Merchant.jsx、admin/*
  components/       人物上传、模板使用统计、趋势图
config/runninghub.example.json
```

## 安全与隐私

- 密码使用 scrypt 加盐存储，会话令牌只在数据库中保存哈希；登录失败有限流
- 人物照片、白模上传和作品保存在 `data/files/private`，只能通过 2 小时有效的签名链接访问；模板素材是公开的
- 删除人物模板时会同时删除原始照片
- 用户协议页（`web/src/pages/Agreement.jsx`）只是占位文本，正式上线前需要由法务根据实际运营主体补充完善
